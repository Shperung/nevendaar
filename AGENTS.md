# AGENTS.md — Nevendaar (браузерна ARPG)

Інструкції для AI-агентів (Claude Code, Cursor, Copilot тощо), які працюють у цьому репозиторії.
Прочитай файл повністю перед тим, як змінювати код. Оновлюй його, коли змінюються домовленості.

## 1. Проєкт одним абзацом

**Nevendaar** — браузерна ізометрична action-RPG у дусі Diablo (рух кліком, hack-and-slash,
рандомний лут, дерево навичок, процедурні підземелля) з візуальним стилем, натхненним
Disciples 2: темне готичне фентезі, пререндерені 2D-спрайти з 8 напрямками.
Спочатку синглплеєр. Мультиплеєр поза скоупом, доки вертикальний зріз не стане цікавим.

**Весь арт оригінальний.** Не посилайся, не копіюй, не називай і не відтворюй жодного
персонажа, юніта, предмета чи ассета з Disciples / Diablo. Запозичується лише *стиль*
(темний, мальований, пререндерений). Назва проєкту — робочий кодонейм, не фінальна.

## 2. Технологічний стек (не змінювати без оновлення цього файлу)

| Область | Вибір | Примітки |
|---|---|---|
| Мова | TypeScript (strict) | `noImplicitAny`, `strictNullChecks` увімкнені |
| Збірка / dev | Vite | `npm run dev`, `npm run build` |
| Рендер | PixiJS 8 | WebGL/WebGPU, лише 2D-спрайти. Без Three.js і Babylon |
| Ігрова логіка | bitECS | Data-oriented ECS. Без ООП-ієрархій сутностей |
| Карти | Tiled (JSON-експорт), ізометрична орієнтація | Завантажує `src/map/TiledLoader.ts` |
| Пошук шляху | easystarjs (A* на сітці) | Обгортка в `src/map/Pathfinder.ts` |
| Збереження | IndexedDB через `idb` | Сейви, налаштування, seed забігів |
| UI | Контейнери PixiJS (HUD, інвентар) | Без React/DOM для внутрішньоігрового UI |
| Тести | Vitest | Юніт-тести для чистої логіки (стати, лут, iso-математика) |
| Лінт / формат | ESLint + Prettier | Запускати перед комітом |
| Пакетний менеджер | npm | Lockfile комітиться |

Заборонено: фізичні движки (Matter, Box2D), веб-експорти Unity/Godot, jQuery, DOM-базований
ігровий UI, тип `any` поза шимами для сторонніх бібліотек.

## 3. Структура репозиторію

```
public/assets/
  atlases/      спрайт-атласи (TexturePacker JSON + PNG)
  maps/         карти Tiled у JSON
  data/         items.json, affixes.json, monsters.json, skills.json
  audio/
src/
  main.ts            лише бутстрап — створити Pixi app, завантажити маніфест, стартувати Game
  config.ts          константи: TILE_W, TILE_H, FIXED_DT, DEBUG-прапорці
  core/              ігровий цикл, стейт-машина, Input, Camera
  ecs/
    world.ts         createWorld(), порядок реєстрації систем
    components/      один файл на компонент, bitECS defineComponent
    systems/         один файл на систему, чисті функції (world) => void
  map/               TiledLoader, IsoMath, Pathfinder, FogOfWar
  gameplay/          ItemGenerator, StatCalc, SkillTree, DungeonGen (чисті, тестовані)
  ui/                Hud, Inventory, Tooltip, Menus (контейнери Pixi)
  assets/manifest.ts бандли Pixi Assets
  save/Storage.ts    обгортка над idb
tools/               Node/Python-скрипти: пакування атласів, рендер спрайтів у Blender, валідація даних
tests/               Vitest-специфікації, що дзеркалять src/
```

Правила:
- `gameplay/` і `map/IsoMath.ts` — чистий TypeScript **без імпортів Pixi**, щоб їх можна було тестувати.
- Системи не створюють Pixi-об'єкти напряму, крім `render.ts` та `ui/`.
- Ігрові дані (предмети, монстри, афікси) живуть у JSON, ніколи не зашиваються в TS.

## 4. Архітектурні правила

### Ігровий цикл
- Фіксований крок логіки 60 Гц (`FIXED_DT = 1/60`), патерн акумулятора в `core/Game.ts`.
- Рендер працює на `app.ticker` з коефіцієнтом інтерполяції `alpha`, який передається в `render.ts`.
- Ніколи не клади ігрову логіку в обробники подій Pixi; обробники лише пишуть у знімок `Input`.

### ECS
- Компоненти — прості структури bitECS `defineComponent`: `Position {x,y}`, `Velocity`, `Sprite`,
  `Health`, `Stats`, `Inventory`, `AI`, `Projectile`, `Loot`, `Player`, `Lifetime`.
- Порядок виконання систем оголошується один раз в `ecs/world.ts`:
  `input → ai → movement → combat → projectiles → loot → lifetime → animation → render`.
- Видалення сутностей відбувається лише в окремому кроці очищення наприкінці кадру.
- Жодних прямих викликів між системами. Спілкування через компоненти або типізовану чергу подій.

### Ізометрична математика
- Ромбічні тайли, `TILE_W = 128`, `TILE_H = 64` (2:1). Світові координати — дробові в тайловому просторі.
- `IsoMath.toScreen(tx, ty)` / `IsoMath.toTile(sx, sy)` — єдині функції конвертації.
- Сортування за глибиною: `zIndex = y_world` у контейнері спрайтів з `sortableChildren = true`.
- 8 напрямків: `N, NE, E, SE, S, SW, W, NW`, індекси 0–7 за годинниковою стрілкою від N.

### Спрайти та анімація
- Кожен атлас персонажа дотримується іменування `{unit}_{anim}_{dir}_{frame}`, напр. `ghoul_walk_3_07`.
- Анімації: `idle`, `walk`, `attack`, `hit`, `death`, опціонально `cast`.
- `animation.ts` обирає кліп за `(state, facing)`; вона нічого не знає про текстури Pixi,
  а пише `Sprite.clipId` і `Sprite.frame`.

### Лут і стати
- Рівні рідкості: `common, magic, rare, unique`. Пули афіксів — в `affixes.json`.
- `StatCalc.compute(base, items, buffs)` — чиста функція; тестуй кожну зміну формули.
- RNG сідований (`mulberry32`), seed зберігається в сейві, щоб забіги були відтворювані.

## 5. Арт-пайплайн (довідково; агенти здебільшого пишуть тулінг для нього)

1. 2D-концепт генерується локально (Stable Diffusion / Flux + LoRA на стилі) → `art/concepts/`.
2. Image-to-3D (Hunyuan3D / Trellis / Tripo) → `art/models/*.glb`.
3. Риг і анімація в Blender / Mixamo → `art/rigged/*.blend`.
4. `tools/render_sprites.py` (Blender headless) рендерить 8 напрямків × усі кліпи → PNG-кадри.
5. `tools/pack_atlas.ts` пакує кадри в атласи в `public/assets/atlases/`.

Агентів можуть просити писати/підтримувати кроки 4–5. Скрипти мають бути ідемпотентними й
параметризованими (назва юніта, список кліпів, кількість кадрів, кут камери за замовчуванням 30°).

## 6. Робочий процес і команди

```
npm install
npm run dev          # dev-сервер Vite
npm run build        # продакшн-збірка в dist/
npm run test         # Vitest
npm run lint         # перевірка ESLint + Prettier
npm run data:check   # валідація JSON-даних за схемами
```

- Малі сфокусовані коміти. Префікси Conventional Commits: `feat:`, `fix:`, `refactor:`, `data:`, `tools:`, `docs:`.
- Додавай або оновлюй Vitest-спеку на будь-яку зміну в `gameplay/` чи `map/IsoMath.ts`.
- Запускай `npm run lint && npm run test` перед тим, як оголосити задачу виконаною.
- Не додавай залежності без обґрунтування в повідомленні коміту й оновлення цього файлу, якщо змінюється стек.

## 8. Як поводитись агенту в цьому репо

- Надавай перевагу редагуванню існуючих файлів, а не створенню паралельних; дотримуйся структури з §3.
- Якщо не впевнений у дизайн-рішенні — коротко запропонуй 2 варіанти і запитай, не обирай мовчки.
- Ніколи не комітити згенеровані ассети > 5 МБ; клади їх в `art/` (у .gitignore) або використовуй LFS.
- Пояснюй неочевидну математику (iso-проєкція, інтерполяція, ваги афіксів) коротким коментарем.
- Тримай цей файл актуальним: змінив домовленість — онови відповідний розділ у тому ж PR.
