# Feature pipeline

Оркеструє субагентів `game-designer`, `tech-planner`, `developer` (`.cursor/agents/`).
Усі артефакти фічі лежать у `docs/features/<NNN-slug>/`: `design.md`, `plan.md`, `report.md`.
Стан фічі визначається полем `Статус:` у `plan.md`: `draft` → `approved` → `done`.

## Визначити фазу

- `/feature <ідея>` — нова фіча: фаза 1.
- `/feature <slug>` або продовження в тому ж чаті — прочитати `plan.md` і продовжити з відповідної фази.

## Фаза 1 — дизайн і план

1. Створити теку `docs/features/<NNN-slug>/` (NNN — наступний номер, slug — англійською, kebab-case).
2. Запустити субагента `game-designer` з ідеєю та шляхом до теки. Дочекатися `design.md`.
3. Запустити субагента `tech-planner` зі шляхом до теки. Дочекатися `plan.md` (`Статус: draft`).
4. **Зупинитися.** Коротко підсумувати користувачу: суть механіки, висновки з Diablo, обсяг змін,
   відкриті питання з обох файлів. Дати посилання на `design.md` і `plan.md`.
   Через AskQuestion запитати: «Погодити план», «Внести правки» (користувач опише), «Скасувати».
5. Правки: застосувати їх у `design.md` / `plan.md` (або перезапустити відповідного субагента) і повторити крок 4.

## Фаза 2 — розробка (лише після явного «погоджую»)

1. Виставити в `plan.md` `Статус: approved`.
2. Запустити субагента `developer` зі шляхом до теки. Дочекатися `report.md`.
3. Самостійно перевірити: `npm run lint && npm run test` проходять, кроки в `plan.md` відмічені.

## Фаза 3 — перевірка користувачем

1. **Зупинитися.** Показати короткий звіт і чекліст «Що перевірити вручну» з `report.md`.
   Через AskQuestion: «Усе працює», «Є баги» (користувач опише).
2. Баги: передати їх `developer` (той самий шлях до теки + опис), повторити фазу 3.
3. «Усе працює»: виставити `Статус: done`, відмітити пункт віхи в `AGENTS.md` §7, якщо фіча його закриває,
   і запропонувати `/commit`.

## Правила

- Ніколи не переходити до фази 2 без явного погодження користувача.
- Не комітити автоматично.
