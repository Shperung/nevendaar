# Арт бічної панелі HUD — план розробки

Статус: done

## Підсумок

Developer-субагент генерує растровий арт панелі через Cursor `GenerateImage` (промпти з `design.md`), сирі
результати кладе в `art/concepts/ui/`, а один ідемпотентний скрипт `tools/uiArt.ts` вирізає magenta-фон,
вписує кожен ассет у точний розмір (2×), робить камінь безшовним і виводить стани медальйона в
`public/assets/ui/`. `Hud.ts` і `Medallion.ts` замінюють декоративні `Graphics` спрайтами
(`Sprite` / `TilingSprite` / `NineSliceSprite`); розкладка, координати, хітбокси, тексти, мінікарта й рідина
самоцвіта не змінюються. Нових залежностей немає (`sharp` уже є).

## Кроки

## Тести

- `tests/tools/imageUtils.test.ts` (синтетичні буфери, без файлів):
  - `opaqueBounds`: квадрат 4×4 у полотні 10×10 → точний bbox; напівпрозорі пікселі (alpha 100) не враховуються;
    порожнє полотно → `null`;
  - `fitPlacement`: `contain` 100×50 у 200×200 → масштаб 2, по центру (`top = 50`); `stretch` 100×50 у 200×200 →
    `scaleX 2`, `scaleY 4`; вписаний bbox завжди в межах box;
  - `cutHole`: чорне коло в центрі сірого квадрата → після виклику центр прозорий, краї ні, bbox ≈ діаметр
    кола; чорний піксель у куті, не зв'язаний із центром, лишається;
  - `deriveMedallionState`: alpha буфера не змінюється; `disabled` — для насиченого пікселя `max − min`
    RGB зменшується ≥ 4 рази; `hover` світліший за `normal`, `pressed` темніший (середня яскравість);
    два виклики на однаковому вході дають однаковий результат.
- `tests/ui/PanelLayout.test.ts`:
  - `medallionLook`: indicator → завжди `normal`; stub без hover → `disabled`, stub з hover → `hover`;
    pressed має пріоритет над hover для звичайної кнопки; stub + pressed → `hover` (натискання заглушки не
    «осідає» текстурою — лише `face.y`, як у design.md; див. ризики);
  - `bandYs`: на висоті 800 — 7 меж блоків + низ (`h − 4`), відсортовано, без y = 0; колона нульової висоти
    не дає двох поясів в одній точці.
- Pixi-частина (спрайти, 9-slice, міпмапи) — ручна перевірка.

## Ризики та рішення

- **Відкрите питання 1 — `reference.png` як вхід `GenerateImage`.** **Рекомендую А з обмеженням**:
  передавати референс лише для якорів (`panel_stone`, `medallion_normal`) і декору з формулюванням
  «material, palette and lighting only», а не для іконок; кожен ассет звіряється поруч із референсом (крок 6).
  Причина — запит користувача «максимально схоже», а копіювання стримується ручною звіркою й тим, що всі
  форми задано текстом. Б (лише текст) — запасний варіант, якщо генерації починають повторювати деталі.
- **Відкрите питання 2 — стани кнопок.** **Рекомендую А** (`normal` генерується, 3 стани виводяться
  `deriveMedallionState`): форма піксель у піксель, у рантаймі лише заміна текстури, логіка тестована.
- **Відкрите питання 3 — іконки.** **Рекомендую А** (растрові, слонова кістка) — так просив користувач і так
  у референсі. Ризик — Tab-кнопка r 11 (при 0.7 ≈ 10 px іконка). Фолбек у межах фічі: для `compass` при
  `size < 14` лишити процедурний силует — **не робимо заздалегідь**, лише якщо при ручній перевірці
  нечитабельно.
- **Відкрите питання 4 — нарізка тла.** **Рекомендую А** (модульно): координати кнопок і вікон з 002 не
  змінюються, висота будь-яка; Б вимагає підганяти `Hud.ts` під арт і перегенеровувати при кожній правці.
- **Власне 1 — атлас чи окремі файли.** (а) ~30 окремих PNG/JPG у `public/assets/ui/` в існуючому бандлі;
  (б) атлас `ui_panel` через `tools/pack_atlas.ts`. **Рекомендую (а)**: `pack_atlas.ts` заточений під
  `{unit}_{anim}_{dir}_{frame}` (регулярка), міпмапи в атласі «протікають» між сусідніми кадрами саме на
  масштабі 0.7, а камінь і 9-slice однаково мали б бути окремими. Шлях — `public/assets/ui/` (як просив
  користувач, поруч із `cursor.png`), а не `atlases/ui/` з design.md. Атлас можна зробити пізніше без змін у
  `Hud.ts` (аліаси ті самі).
- **Власне 2 — міпмапи.** `data: { autoGenerateMipmaps: true }` у записі бандла передається в
  `TextureSource` Pixi 8. Під WebGL2/WebGPU працює для NPOT-текстур; під WebGL1 міпмапи NPOT не генеруються —
  деталі просто мерехтять сильніше, гра не ламається. Перевірити на масштабі 0.7.
- **Власне 3 — вписування рамок за вікном.** Генерація ніколи не дасть вікно точно 160×120; `cutHole` знаходить
  реальне чорне вікно й мапить його на цільовий прямокутник (`stretch`). Якщо вікно в генерації не чисто чорне
  (відблиски, текстура) — flood зупиниться раніше; тоді перегенерувати або підняти поріг у таблиці для цього
  ассета. Для `gem_mount` вікно кругле — мапимо bbox кола.
- **Власне 4 — формула іконки з design.md.** `(size · 0.9) / 20` для 40-px іконки дає сторону `1.8 · size`,
  тобто іконка більша за кільце. План: іконка вписана в 72/80 полотна, сторона на екрані `size · 1.3`
  (≈ внутрішній диск `0.72 · size` у діаметрі з запасом на прозорі поля), константа `ICON_SCALE` у
  `Medallion.ts`.
- **Власне 5 — pressed для заглушки.** Design: заглушка показує `disabled`, на hover — `hover`. Натискання
  заглушки дає лише зсув на 1 px без `pressed`-текстури, щоб не виглядало, як ніби дія спрацювала.
- **Власне 6 — молдинг на всю висоту.** Розтяг 400-px смуги до ~2000 дизайн-px (висота 1440 / 0.7) розмиє
  нерівності арту. Промпт вимагає однорідності вздовж Y, тож прийнятно. Якщо видно — замінити `Sprite` на
  `TilingSprite` по Y (потрібна вертикально-безшовна смуга, `seamless.ts` уміє лише квадрат) — поза планом.
- **Власне 7 — magenta-ореол.** На бронзі з теплими відтінками `removeKeyColor` може лишити рожеву кайму на
  анти-аліасингу. Перевіряти на темному тлі; якщо є — у `uiArt.ts` після ключа ерозія alpha на 1 px.
- **Власне 8 — вага.** 2× PNG з painterly-текстурою: оцінка ~0.8–1.2 МБ. Якщо > 1.5 МБ — іконки й
  `parchment` через `png({ palette: true })`, камінь уже `.jpg`.
- **Залежності.** Нових немає: обробка на `sharp` (вже в devDependencies), рантайм — Pixi 8
  (`TilingSprite`, `NineSliceSprite` уже в пакеті).
