# Артефакти — звіт

## Що зроблено

- **Дані.** `monsters.json` — `level` (1 / 2 / 3); `loot.json` — `_rarity` і `items { rolls, chance }`;
  нові `items.json` (20 баз, 12 unique, `rareNames`) і `affixes.json` (7 префіксів + 6 суфіксів) з таблиць
  `design.md`. `icon` бази — `item_<baseId>`, unique — `unique_<uniqueId>` (перевіряється тестом).
- **Чиста логіка.** `gameplay/Items.ts` — типи, `parseItemData` з перехресними перевірками, `restoreItems`;
  `gameplay/ItemGenerator.ts` — `rollItem` (база → рідкість → unique/афікси → назва rare) і `weighted`;
  `parseLoot` читає `_rarity` і `items`; `MonsterDef.level`.
- **Тексти.** `ui/ItemText.ts` — назви з узгодженням роду, модель картки, `sackLabel` з відмінюванням,
  `topRarity`, `RARITY_INK` / `RARITY_GLOW`, `TYPE_NAMES`.
- **ECS.** `ItemDrop`, side-map'и `SackItems` і `Backpack`; `loot.ts` роллить золото, потім артефакти,
  кладе все в одну сутність, при підборі дописує артефакти в кінець `Backpack` (ліміт `BACKPACK_CAP`);
  `cleanup.ts` чистить `SackItems`; лічильник `uid` стартує з `max(uid) + 1`.
- **Збереження.** `Storage.loadInventory/saveInventory` (ключ `nevendaar.inventory`); `Game` зберігає
  список, коли змінюється довжина `Backpack`.
- **Візуал.** `render.ts` — мішечок (`loot_sack` або `Graphics`-фолбек) з аурою кольору найвищої рідкості,
  що пульсує раз на 1.5 с, і підписом наведення; `ui/FindLog.ts` — журнал «Знайдено: …» (≤ 5 рядків,
  4 с, згасання); `InventoryWindow.setItems` — клітинки з іконкою або плейсхолдером, рамка кольору рідкості,
  прокрутка; пергаментна картка з `cardPosition`.
- **Тулінг.** `tools/uiArt.ts` — іконки з `items.json` → `ui/items/<icon>.png` 128×128 (`contain`,
  box 4/4/120/120), `mkdir` підтеки, фільтр `items` бере всю групу, записи `card_frame` (600×600) і
  `card_icon_frame` (160×160, обидва `stretch` + `STONE`). Відсутні сирі файли пропускаються з попередженням
  (як і раніше в тулі).
- **AGENTS.md** — §3 `ui/items/`, §4 «Лут і стати».
- Скріншот картки з плейсхолдерами — `screenshot-card.jpg`.

## Відхилення від плану (і чому)

- **Арт (крок 6).** Developer зробив лише зміни в `tools/uiArt.ts`. Сирі зображення, запуск `uiArt.ts`
  і `keyCutout.ts` та коміт виходу робить оркестратор. Код працює без арту на фолбеках.
- **Крок 1: завантаження в `main.ts`** під'єднано одразу до `Game` (кроки 4–5), бо `noUnusedLocals` не
  пропускає змінну, яка «поки не використовується». З тієї ж причини `restoreItems` написано разом із
  `parseItemData`.
- **Запит на смерть у `loot.ts`** тепер `[Dead, Position]` з перевіркою `GoldDrop`/`ItemDrop` через
  `hasComponent`, щоб монстр без золота, але з `items`, теж міг щось скинути.
- **Типи.** У `AffixDef` назви суфікса нормалізовані до `names: { m, f, pl }` (усі три форми однакові), тож
  назва збирається однаково для обох видів. `Item.affixes` — union `{ id, tier, value } | { stat, value }`
  (як у `design.md`, одне поле). `ItemCard` має ще `icons` (ланцюжок unique → база) і `letter`
  (літера плейсхолдера).
- **Rare на крайових даних.** Вид наступного афікса обирається 50/50 лише серед видів, які ще мають
  кандидатів і не вичерпали ліміт 2, тому база з одним префіксом без суфіксів стабільно дає rare з 1 афіксом
  (як вимагає тест у плані).
- **`group` = `stat`** (як у прикладі `design.md`). Наслідок: префікс і суфікс з тим самим статом
  (`sturdy`/`of_vigil`, `jagged`/`of_wrath`, `hasty`/`of_carnage`, `stalwart`/`of_marrow`) не трапляються
  на одному предметі. Якщо це небажано, достатньо дати суфіксам окремі `group` у JSON, код міняти не треба.
- **Клітинка common** лишає звичайну рамку; кольорова рамка — лише для magic/rare/unique.
- **Скріншот** збережено як `.jpg` 1280 px, бо PNG важив 8.8 МБ.
- **`npm run data:check`** не запускався: такого скрипта немає в `package.json`. Дані валідуються
  `parseItemData`/`parseLoot` під час запуску гри й у тестах.

## Що перевірити вручну

1. `npm run dev`, відкрити гру; у консолі немає помилок завантаження даних. Поки немає
   `loot_sack.png`, у консолі буде одне попередження «loot_sack.png not found…»; це очікувано.
2. Вбивати монстрів: частина лишає купку монет 001, частина — мішечок (без арту — коричневий ромб із
   зав'язкою); навколо мішечка з magic/rare/unique пульсує аура відповідного кольору, у common аури немає.
   До кінця `pickupDelay` мішечок притемнений.
3. Навести на мішечок — підпис «Мішечок: N золота, K артефакт(и/ів)» кольором найвищої рідкості.
4. Підійти — мішечок зникає, золото в HUD росте, ліворуч знизу з'являються рядки «Знайдено: …» кольором
   рідкості, згасають за ~4 с, не більше 5 одночасно.
5. `I` — у рюкзаку клітинки з іконками (або плейсхолдерами-літерами типу) у порядку підбору, рамка кольору
   рідкості. Наведення показує пергаментну картку: іконку в рамці, назву кольором рідкості, для rare — назву
   бази, підрядок «… артефакт · рівень N», тип і базовий стат, афікси, для unique — flavor курсивом. Біля
   краю екрана картка не вилазить за межі. Без `card_frame.png` у картки проста бронзова рамка.
6. Набрати > 40 предметів (тимчасово підняти `items.chance` у `loot.json` до 1) — з'являються нові рядки,
   рюкзак прокручується колесом.
7. Перезавантажити сторінку — предмети в рюкзаку ті самі, в тому ж порядку; нові знахідки йдуть у кінець.
8. Тимчасово перейменувати одну іконку в `public/assets/ui/items/` і `loot_sack.png` — гра працює з
   плейсхолдером і `Graphics`-мішечком.

Під час перевірки в браузері (порт 5179) у `localStorage` цього origin лишився тестовий інвентар із
4 артефактами. На origin звичайного dev-порту 5173 це не впливає.
