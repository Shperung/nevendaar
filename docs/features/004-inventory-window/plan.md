# Вікно інвентаря — план розробки

Статус: done

## Підсумок

Модальне вікно інвентаря на нативному `<dialog>` + CSS (без фреймворків): ліва колонка-пергамент зі статами
героя (оновлюються наживо), центр — намальована картина «герой на повний зріст у готичній залі» з 10 порожніми
ромбічними слотами поверх, рюкзак 10×4 знизу. Відкривається медальйоном «Інвентар» у HUD і клавішею `I`,
закривається `I` / `Esc` / «×». Гра **не** ставиться на паузу: вікно лише блокує керування героєм. Арт
центру й ромба слота генерується через наявний UI-арт пайплайн; решта — CSS-заглушки з наявними текстурами.
HUD лишається на Pixi; `AGENTS.md` оновлюється під домовленість «модальні вікна — DOM `<dialog>`».

## Ризики та рішення

- **Без паузи — що блокує вікно.** Фіксований цикл не чіпаємо: світ (AI, бій, анімації, респаун) тікає далі.
  Блокується лише керування героєм:
  - кліки по світу: `::backdrop` модального `<dialog>` лежить поверх canvas, тож `pointerdown` до Pixi-сцени
    не доходить (Pixi слухає його на canvas); клік по затемненню нічого не робить — дефолт `showModal`
    (без `closedby="any"`);
  - утримання ЛКМ: `onChange` при відкритті й закритті ставить `Input.click = null`, `Input.held = false`
    (інакше утримана перед `I` кнопка лишилася б «натиснутою» й `input`-система далі переводила б героя на
    курсор);
  - інші хоткеї — гілка `isOpen → return` в обробнику клавіатури (нижче).
- **Поточний рух героя при відкритті — не зупиняємо.** Варіанти:
  - А (обрано): нічого не скасовувати. Герой дійде до вже обраної точки (шлях — кілька тайлів), а атака
    зупиниться після поточного удару: зі скиданням `Input.held` система `input` ставить
    `AttackTarget.repeat = 0`, і `combat` знімає ціль після удару. Жодних змін в ECS/системах, UI не пише в
    компоненти; поведінка як у Diablo.
  - Б: зупиняти героя миттєво — потребує нового поля `Input.stop` і гілки в `input`-системі (зняти `Path`,
    `MoveTarget`, `AttackTarget`). Більше коду заради рідкісного випадку; відкладаємо, якщо гравці скаржитимуться.
- **Живі стати.** Поки вікно відкрите, тікер щокадру викликає `inventoryWindow.update(heroStats())`;
  вікно переписує `textContent` лише рядків, що змінилися (як `hud.update`), тож DOM не смикається 60 разів
  на секунду. Закрите вікно не оновлюється.
- **Хоткеї й `Esc`.** Єдиний `keydown` на `window` у `Game.ts` (уже є для `F`):
  `if (e.repeat) return; if (KeyI) toggleInventory(); else if (inventoryWindow.isOpen) return; else if (KeyF) toggleFullscreen();`.
  - `I` працює й при відкритому вікні: фокус на «×» усередині `<dialog>`, подія спливає до `window`.
  - `Esc` закриває вікно **нативно** (`cancel` → `close`), коду для нього немає. `keydown` спливає до `window`
    _до_ дефолтної дії, тож у обробнику `isOpen` ще `true` і майбутнє меню `Esc` (зараз заглушка) у цьому ж
    натисканні не відкриється.
  - Обробники лише перемикають вікно (UI-стан) і пишуть у `Input`; ігрової логіки в них немає.
- **Медальйон.** Натискання медальйона не доходить до сцени (`Hud` гасить `pointerdown`). Стан `pressed`
  виставляє `onChange` через `setActive` — синхронно і при закритті через `Esc`/«×». При відкритті ховаємо
  Pixi-тултіп, інакше він лишиться під затемненням.
- **Мертвий герой.** `toggleInventory` не відкриває вікно, якщо `hasComponent(world, Dead, hero)` (зараз
  респаун миттєвий, тож це захист на майбутнє). Смерть при відкритому вікні його не закриває — стати
  показують стан після респауну.
- **Арт фігури: цілісна картина чи вирізаний герой поверх зали.** Варіанти:
  - А (обрано): одна картина `inv_doll` (герой + зала + туман) з власним фоном, без вирізання, `.jpg`.
    Фігура однаково статична (не змінюється від екіпіровки), тож шарувати немає сенсу; туман і світло
    природно огортають фігуру, нема magenta-кайми навколо м'яких країв; одна генерація замість двох; JPEG
    дрібніший за PNG з альфою. Потрібна лише невелика гілка `opaque` в `tools/uiArt.ts`.
  - Б: `inv_hall` (тло) + `inv_hero` (magenta → вирізання) окремо — пайплайн уже це вміє, але дає ореол на
    тумані/волоссі, дві генерації й ризик невідповідності світла. Має сенс лише коли фігура стане динамічною.
- **Розмір ассетів.** `inv_doll.jpg` 1376×800 при якості ≈ 82 — орієнтовно 300–450 КБ, `slot_diamond.png`
  ≈ 30 КБ; разом `public/assets/ui/` ≈ 1.3 МБ — далеко від ліміту 5 МБ (`AGENTS.md` §8). Сирі генерації — в
  `art/` (поза git). Перевірка розміру — у підсумку `uiArt.ts`.
- **Композиція генерації.** `GenerateImage` може дати інше співвідношення сторін; `cover` обріже краї. Тому в
  промпті герой у центральній третині й ноги на ≈ 70 % висоти, а крок 5 включає візуальну перевірку й
  перегенерацію.
- **Решта арту.** `inv_frame`, `inv_parchment`, `cell_frame`, `ghost_*` не генеруємо: рама — `panel_stone.jpg`
  - CSS, таблички — `parchment.png`/бежевий, клітинки — CSS-рамка, силуети — наявні `icon_helmet`/`icon_sword`
    для двох слотів, решта без силуету. `slot_diamond` генеруємо, бо 10 ромбів — головний візуальний елемент
    поверх картини, а CSS-ромб на ній виглядає чужорідно.
- **Анімація** відкриття/закриття — чистий CSS (`@starting-style`, `transition-behavior: allow-discrete`).
  У старих браузерах просто без анімації.
- **Масштаб.** Вікно має фіксований дизайн-розмір 960×640 CSS-px і `transform: scale(var(--scale))`;
  `--scale` перераховується в `resize()` з `app.renderer.on('resize')`. Вікно по центру всього екрана, поверх
  гри й бічної панелі (top layer `<dialog>`).

## Ухвалені рішення (колишні відкриті питання)

1. **Пауза — ні.** Світ живе, вікно блокує лише керування героєм; поточний наказ героя доводиться до кінця;
   стати оновлюються наживо.
2. **Рюкзак** — повна сітка 10×4 без прокрутки.
3. **Фігура героя** — окремий намальований оригінальний арт на повний зріст у готичній залі (`inv_doll`,
   цілісна картина без вирізання), не кадр спрайта.
4. **Медальйон «Персонаж» (`C`)** — лишається заглушкою.

2. Навести на медальйон «Інвентар» — тултіп «Інвентар (I)» без «Ще недоступно». Клікнути — екран

3. У вікні: ліворуч ім'я «Вотан», здоров'я `100 / 100`, шкода 10, швидкість атаки `2.0 / с`, дальність
   `1.2 тайла`, швидкість руху `4.0 тайла/с`, золото (з сейву), глибина 1; у центрі картина героя в залі й
   10 ромбів з тултіпами назв при наведенні, ромби не перекривають фігуру; унизу 40 клітинок, наведення
   підсвічує.
4. Клікнути далеко по землі й одразу натиснути `I` — герой доходить до точки й зупиняється.
5. Почати бій і натиснути `I` — монстри продовжують бити, здоров'я у вікні падає наживо; після смерті й
   респауну вікно лишається відкритим зі здоров'ям `100 / 100`.
   5a. Клікнути по купці золота й одразу натиснути `I` — герой доходить і підбирає її, золото у вікні зростає.
6. Утримуючи ЛКМ (герой іде за курсором), натиснути `I` — герой зупиняється в кінці поточного шляху й не
   «тягнеться» за курсором; після закриття не рушає сам.
7. Закрити кожним способом: `I`, `Esc`, «×» — медальйон щоразу повертається в `normal`.
8. Клік по затемненню — нічого; після закриття герой не рушає туди, де був клік.
9. При відкритому вікні `F` не перемикає повний екран; `Tab` ходить лише всередині вікна. `C` — як і раніше
   заглушка.
10. Змінити розмір вікна браузера при відкритому інвентарі — вікно масштабується й лишається по центру.
