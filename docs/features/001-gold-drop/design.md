# Дроп золота з монстрів — геймдизайн

## Ідея

Монстр при смерті з певним шансом залишає на землі купку золота. Герой підбирає її, і золото
додається до його гаманця (лічильник на HUD). Це перший шматок луту у віхі §7 п.5.

## Як це в серії Diablo

- **D1:** золото — окремий предмет на землі, підбирається кліком. Займає клітинку інвентаря,
  стакається до 5000 у клітинці, тобто конкурує з предметами за місце. Кількість залежить від рівня
  підземелля. Візуал — купки різного розміру залежно від суми.
- **D2:** кількість залежить від рівня монстра (treasure class) + стат «Gold Find %». Спершу підбір
  кліком, у D2R додали опцію автопідбору при проходженні поверх. Ліміт у кишені = рівень × 10 000,
  у сховищі — окремий ліміт. Смерть забирає частину золота (штраф), ще частина лишається в трупі.
  Купки 3–4 розмірів, підпис суми при наведенні/Alt.
- **D3:** повний автопідбір у радіусі (стат «Gold Pickup Radius» збільшує його), «+N gold»
  спливає над героєм, кілька купок за раз з одного монстра, розліт по колу. Ліміту фактично немає.
  Інфляція через аукціон: золото знецінилось — урок про контроль джерел.
- **D4:** автопідбір, золото з монстрів, скринь, продажу. Масштабується з рівнем, витрачається на ремонт
  і крафт. Купки підсвічені, малі суми часто не помічаються — гравці вважали дроп «шумом».
- **Immortal:** автопідбір, золото підбирається навіть з далекої відстані/після бою; основні суми — з
  активностей, а не з мобів; є денні обмеження джерел.
- **Висновки:**
  - Беремо: автопідбір при наближенні (усі сучасні частини прийшли до цього, клік по кожній купці —
    рутина), купки різного розміру залежно від суми, сідований рандом навколо базового значення.
  - Беремо частково: кількість від «рівня» — поки рівнів монстрів немає, тож база задається на тип
    монстра з множником рівня зони на майбутнє.
  - Відкидаємо зараз: золото в інвентарі як предмет (D1), ліміти гаманця, Gold Find / Pickup Radius
    афікси, штраф за смерть (D2) — золото ні на що не витрачається, штраф лише дратуватиме.
  - Урок D3/D4: золото має бути рідшим і вагомішим, ніж «дощ монет» — шанс < 100%.

## Як це працює в Nevendaar

**Дроп**

- Тригер: монстр отримав `Dead` (не герой). Рол виконується один раз, до видалення сутності.
- Запис дропу шукається в `loot.json` за id монстра; немає запису або немає `gold` — нічого не падає.
- Шанс: `roll < gold.chance` (сідований `mulberry32` з seed забігу; той самий RNG для суми й зсуву).
- Сума: `max(1, round(base · (1 + U(-spread, +spread))) · zoneGoldMult)`, де `U` — рівномірне число
  з RNG, `spread` ∈ [0, 1) (частка від бази), `zoneGoldMult` — зараз 1, у майбутньому рівень підземелля.
  Приклад: `base = 10, spread = 0.3` → 7..13.
- Одна купка на монстра. Позиція — місце смерті + випадковий зсув до 0.3 тайла; якщо тайл заблокований
  — кладемо точно в місце смерті (воно завжди прохідне).
- Купка — окрема сутність: позиція, сума, таймер затримки підбору. Не блокує рух, не має здоров'я,
  не є ціллю атаки.

**Підбір**

- Затримка: купка стає доступною для автопідбору через `pickupDelay` секунд після дропу (дані, зараз 2 с).
  Таймер іде у фіксованому кроці логіки, не в реальному часі.
- Автопідбір: якщо затримка минула і герой у радіусі `pickupRadius` тайла (зараз 0.6, тобто «стоїть
  поверх»), сума додається до гаманця, купка видаляється в кроці очищення.
- Якщо герой стоїть на купці, поки затримка ще не минула, — купку забирає в той кадр, коли затримка
  закінчиться (ходити туди-сюди не треба).
- Клік по купці (коли під курсором немає монстра) = рух до неї; підбір спрацює сам за правилами вище.
  Пріоритет кліку: монстр > купка > земля.
- Мертвий герой не підбирає. Кілька доступних купок у радіусі — підбираються всі за один крок.

**Гаманець**

- Ціле число на герої, старт 0, без верхньої межі (запобіжник — `Number.MAX_SAFE_INTEGER`).
- Смерть і респаун: штрафу немає, золото зберігається повністю.
- Зберігається між сесіями в `localStorage` через обгортку збереження (`save/Storage.ts`): записується
  при кожній зміні суми, читається на старті гри. Битий або відсутній запис → 0.
- Купки на землі між сесіями не зберігаються (карта й монстри поки генеруються наново).

**Крайові випадки**

- Купки лежать вічно, не зникають і не зливаються. Купка під перешкодою неможлива — див. позицію.
- Монстр, що помер без удару героя (у майбутньому — від іншого джерела), дропає так само.

## Дані

Новий файл `public/assets/data/loot.json`. Ключ — id монстра (як у `monsters.json`), значення — таблиця
дропу. Зараз у ній лише `gold`; пізніше поруч з'явиться `items` (артефакти) без зміни формату `gold`.
Загальні параметри підбору — у службовому ключі `_pickup` (з `_` не може починатися id монстра).

```json
{
  "_pickup": { "pickupDelay": 2, "pickupRadius": 0.6 },
  "skeleton": { "gold": { "chance": 0.4, "base": 4, "spread": 0.5 } },
  "zombie": { "gold": { "chance": 0.5, "base": 6, "spread": 0.4 } },
  "necro_warrior": { "gold": { "chance": 0.6, "base": 10, "spread": 0.3 } }
}
```

Майбутнє розширення (не робимо зараз, лише щоб формат не довелось ламати):

```json
"necro_warrior": {
  "gold":  { "chance": 0.6, "base": 10, "spread": 0.3 },
  "items": { "rolls": 1, "chance": 0.15, "pool": [ { "id": "rusted_blade", "weight": 3 } ] }
}
```

Пороги розміру купки (лише візуал) — константи конфігу: сума ≤ 5 → `gold_small`, ≤ 15 → `gold_medium`,
більше → `gold_large`.

## Що бачить гравець

- Після смерті монстра на землі з'являється купка монет (з кроком «викидання»: коротке підстрибування
  0.2 с — опційно). Розмір: мала / середня / велика за сумою.
- Купка має ледь помітне мерехтіння-відблиск, щоб її було видно на снігу. Перші 2 с (поки підбір
  недоступний) купка трохи притемнена — гравець бачить, чому вона ще не підбирається.
- При наведенні курсора — підпис «12 золота» над купкою (placeholder — Pixi Text).
- Підбір: купка зникає, число на HUD оновлюється.
- HUD: іконка монети + число поруч зі смужкою здоров'я героя.
- Placeholder: купка — жовтий ромбик/коло 3 розмірів; число на HUD — Pixi Text.

## Візуал і ассети

**Арт-дирекшен.** Не яскраве «аркадне» золото, а потемніле, стерте старе карбування: глибока охра,
бронзові тіні, теплі відблиски лише на гранях. Монети грубі, нерівні, частина почорнілі; карбування —
оригінальний символ (стилізоване око в колі з променями), без гербів. Великі купки з домішкою брудного
снігу, клаптів шкіри від гаманця. Силует низький і плаский, читається на тлі снігу й темного ґрунту
завдяки теплому контрасту. Ракурс ізометричний 30°, тінь під купкою м'яка. Генерувати на рівному
зеленому тлі для `tools/keyCutout.ts` (режим `green`).

Ассети: `gold_small` (3–5 монет), `gold_medium` (жменька + розірваний мішечок), `gold_large`
(висипана купа з мішка), `ui_coin` (іконка HUD), `fx_gold_glint` (відблиск, 4–6 кадрів).

Базовий хвіст: `dark gothic fantasy, pre-rendered 2D sprite, painterly oil illustration, muted earthy palette, dramatic soft lighting, isometric 30 degree view, highly detailed, grim atmosphere`
Базовий негатив: `cartoon, anime, chibi, pixel art, flat colors, bright saturated, cel shading, modern, sci-fi, text, watermark`

- **gold_small**
  - +: `a few scattered old tarnished gold coins lying on the ground, crude uneven hand-struck coins with a worn eye-and-rays emblem, some blackened, small soft shadow, isolated on flat green background, ` + базовий хвіст
  - −: базовий негатив + `, shiny new coins, euro, dollar, glowing, sparkles, treasure chest, hand, ground texture`
- **gold_medium**
  - +: `a small handful of tarnished gold coins spilling from a torn worn leather pouch, dirty snow flecks, crude hand-struck coins, warm dim highlights on coin edges, isolated on flat green background, ` + базовий хвіст
  - −: базовий негатив + `, shiny new coins, glowing, sparkles, jewels, treasure chest, hand`
- **gold_large**
  - +: `a heap of old tarnished gold coins poured out of a ripped blood-stained leather sack, a few bone fragments and dirty snow, crude hand-struck coins with worn emblem, warm torchlight glints on edges, isolated on flat green background, ` + базовий хвіст
  - −: базовий негатив + `, shiny new coins, glowing aura, gems, treasure chest, skeleton, hand`
- **ui_coin**
  - +: `single old tarnished gold coin icon, front view, crude hand-struck coin with worn eye-and-rays emblem, chipped edge, dark aged patina, warm rim light, centered, isolated on flat green background, dark gothic fantasy, painterly oil illustration, muted earthy palette, highly detailed`
  - −: базовий негатив + `, isometric, multiple coins, shiny new coin, glowing, frame, border`

  - +: `small soft warm golden glint sparkle, four pointed star of light with faint haze, subtle and dim, isolated on pure black background, painterly oil illustration, dark gothic fantasy`

## Поза скоупом

- Золото як предмет в інвентарі, ліміт гаманця, сховище.
- Афікси Gold Find / радіус підбору, штраф золотом за смерть.
- Витрати золота (торговці, ремонт, крафт) — §7 явно відкладає торговців.
- Зникання купок з часом, злиття сусідніх купок, кілька купок з одного монстра.
- Золото зі скринь/бочок, елітні/боси з бонусним золотом.
- Звук монет.
- Спливаючий «+N» над героєм при підборі.
- Дроп артефактів (`items` у `loot.json`) — лише зарезервовано місце у форматі.
- Збереження купок на землі між сесіями.

## Рішення

1. **Підбір** — автоматичний із затримкою: купка доступна через `pickupDelay` = 2 с після дропу, далі її
   забирає герой у радіусі `pickupRadius`. Клік по купці веде героя до неї. Обидва параметри — у даних.
2. **Гаманець** — зберігається між сесіями в `localStorage` через обгортку збереження. Штрафу за смерть
   немає. Примітка: `AGENTS.md` §2 фіксує IndexedDB через `idb`; обгортка має дозволити пізніше
   змінити бекенд без змін у геймплеї, а розбіжність зі стеком варто відобразити в `AGENTS.md`.
3. **Параметри дропу** — окремий `public/assets/data/loot.json`, ключ — id монстра, таблиця з `gold`
   і зарезервованим місцем під `items`.
4. **Купки** лежать вічно.
5. **«+N» над героєм** — поза скоупом; лічильник на HUD лишається.
6. **Сума** — `base ± spread`: `max(1, round(base · (1 + U(-spread, +spread))) · zoneGoldMult)`,
   RNG — сідований `mulberry32` забігу.
