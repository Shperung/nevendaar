# Бічна панель HUD — план розробки

Статус: done

## Підсумок

Теперішній HUD (лічильник золота в лівому верхньому куті) і кнопка повного екрана замінюються однією
непрозорою процедурною панеллю праворуч на всю висоту екрана (`ui/Hud.ts`, лише Pixi `Graphics`/`Text`/`Sprite`).
Панель масштабується від висоти вікна, поглинає ввід, а камера центрує героя в ігровій зоні ліворуч від неї.
На панелі працюють мінікарта, портрет із пергаментом (ім'я, HP, золото), самоцвіт здоров'я і кнопка
повного екрана (+ хоткей `F`); решта медальйонів — заглушки з тултіпом. Геометрія панелі — чиста
функція без Pixi, покрита Vitest.

## Тести

- `tests/ui/PanelLayout.test.ts`:
  - висота `800` → `scale = 1`, `width = 200`, `columnH` = базова висота колони;
  - висота `400` → `scale = 0.7` (нижня межа), `columnH` = `max(0, 400/0.7 − FIXED_H)`; висота `1600` →
    `scale = 1.4`, лишок пішов у `columnH`;
  - вузьке вікно `600 × 1000` → `width ≤ 40 %` ширини, але `scale ≥ 0.7`;
  - `x + width === screenW` завжди;
  - блоки йдуть зверху вниз без перекриттів; блоки під колоною зсуваються рівно на зміну `columnH`;
  - `clampTooltip`: біля верхнього/нижнього краю результат у `[0, screenH − h]`;
  - `healthFraction`: `87/100 → 0.87`, `0/100 → 0`, `max = 0 → 0`, `120/100 → 1`, від'ємне → 0.
- `PanelLayout.ts` не імпортує `pixi.js` — інакше тест не підніметься без WebGL (це і є перевірка правила).
- Pixi-частина (малювання, мінікарта, тултіп) не тестується юніт-тестами — ручна перевірка.

## Ризики та рішення

- **Відкрите питання 1 — масштаб.** **Рекомендую А** (масштаб від висоти + тягнуча колона): одна
  формула в `PanelLayout`, панель однаково виглядає на 768p і 1440p; Б на 4K дає вузьку смужку.
- **Відкрите питання 2 — монстри на мінікарті.** **Рекомендую А** (з монстрами): ті самі крапки, що й
  золото, одна додаткова query; корисно для тестування спавну. Прибрати — один рядок.
- **Відкрите питання 3 — здоров'я.** **Рекомендую А** (самоцвіт + рядок): самоцвіт — головний
  елемент кільця, без нього центр панелі порожній; вартість — одна маска й прямокутник.
- **Відкрите питання 4 — дубль глибини.** **Рекомендую А** (лічильник над кільцем, табличку прибрати):
  менше `Text`, одне джерело; під мінікартою лишається вузька смуга з медальйоном Tab.
- **Відкрите питання 5 — тултіп заглушок.** **Рекомендую А**: `Tooltip` однаково потрібен для
  самоцвіта й кнопки повного екрана, для заглушок це лише інший текст.
- **Відкрите питання 6 — `F`.** **Рекомендую А**: один `keydown`, дія вже є.
- **Власне 1 — де чиста геометрія.** AGENTS.md вимагає чистоти для `gameplay/` і `IsoMath`; геометрія
  панелі — UI, але її варто тестувати. **Рекомендую** `src/ui/PanelLayout.ts` без імпортів Pixi
  (поруч зі споживачем) замість `gameplay/` (там лише ігрові правила). Альтернатива — `src/core/`.
- **Власне 2 — мінікарта: текстура чи живе малювання.** (а) Вся місцевість один раз у текстуру
  `1280 × 640` (~20 тис. ромбів перешкод малюються один раз, далі лише зсув спрайта); (б) щокадру
  малювати лише ~40 × 30 тайлів навколо героя. **Рекомендую (а)** — як у design.md, і кадр дешевший.
  Коли з'являться процедурні рівні й туман війни — текстура перегенеровується на карту, туман — окремий шар.
- **Власне 3 — ввід над панеллю.** (а) `stopPropagation` на `pointerdown` панелі + заморожування
  `pointerScreen` за `e.global.x ≥ hud.x`; (б) окремий DOM-оверлей. **Рекомендую (а)**: DOM заборонено
  §2, а `pointerup` з панелі все одно спливає на `stage` і знімає утримання.
- **Власне 4 — смерть героя.** `cleanup` респаунить героя в тому ж кроці, тож «порожній самоцвіт до
  респауну» гравець не побачить — окремого стану не робимо, самоцвіт просто показує `Health`.
  Чи потрібна видима пауза смерті — питання до майбутньої фічі респауну.
- **Власне 5 — продуктивність мінікарти.** Щокадру прохід по ~1500 купках і ~3000 монстрах із
  відсіканням за вікном. Для вертикального зрізу ок; якщо стане помітно — оновлювати крапки раз на 3–4 кадри.
- **Власне 6 — чіткість тексту при масштабі 1.4.** `Text` масштабується разом із контейнером і
  розмиється. Рішення: при `layout` ставити `resolution = devicePixelRatio · scale` для текстів панелі
  (кілька рядків, дешево).
- **Власне 7 — `FullscreenButton.ts`.** Видаляємо, а не лишаємо паралельно: друга кнопка в правому
  верхньому куті опинилась би під панеллю.
- **Залежності.** Нових немає.

## Як перевірити вручну

1. `npm run dev`: праворуч — темна кам'яна колона на всю висоту, старого лічильника золота й кнопки
   у верхніх кутах немає; герой по центру зони ліворуч від панелі.
2. Змінити висоту вікна: панель масштабується, тягнеться лише колона між рядом кнопок і портретом;
   дуже низьке вікно — низ обрізається, нічого не налазить одне на одне. Вузьке вікно — панель ≤ 40 % ширини.
3. Піти героєм до правого краю — камера зсувається раніше, ніж герой зайде під панель.
4. Клік і утримання на панелі — герой не рухається. Затиснути ЛКМ на сцені й завести курсор на
   панель — герой іде до точки біля межі; відпустити над панеллю — утримання знімається.
5. Курсор над купкою біля межі, потім на панель — підпис «N золота» зникає.
6. Навести на заглушку — золота рамка, тултіп «Інвентар (I)» / `Ще недоступно` ліворуч; затиснути —
   медальйон вдавлюється, нічого не відбувається. Тултіп біля верху/низу екрана не виходить за край.
7. Кнопка повного екрана й `F` — вхід/вихід, іконка й тултіп міняються; вихід через Esc браузера теж
   синхронізує іконку.
8. Мінікарта: герой у центрі, місцевість зсувається при ході, видно купки й монстрів; убити монстра —
   крапка зникає, з'являється жовта.
9. Отримати удар — самоцвіт і рядок `Здоров'я` в пергаменті зменшуються; підібрати золото — сума в
   пергаменті зростає; портрет — герой.
